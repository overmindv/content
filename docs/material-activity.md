# События материалов

Новые события включаются через `CONTENT_ACTIVITY_ENABLED=true` и
`KAFKA_ENABLED=true`. Сначала создай топики и выдай доступ нужным сервисам.
Все три имени должны отличаться друг от друга и от `KAFKA_TOPIC`.

| Переменная | Топик по умолчанию | События |
| --- | --- | --- |
| `KAFKA_CONTENT_MATERIAL_TOPIC` | `content.material.v1` | `material.published`, `material.archived`, `material.withdrawn`, `material.restored`, `material.corrected` |
| `KAFKA_CONTENT_CONTRIBUTION_TOPIC` | `content.contribution.v1` | `contribution.merged`, `review.accepted` |
| `KAFKA_CONTENT_LEARNING_TOPIC` | `content.learning.v1` | `material.read_confirmed` |

Ключ Kafka: UUID материала. JSON-тип в Go: `pkg/api/activity.Event` с типом
полезной нагрузки для соответствующего потока. Общие поля: `event_id`,
`event_type`, `schema_version` (1), `occurred_at`, `aggregate_id`,
`aggregate_version`, `revision_id` (ID опубликованной версии) и `payload`.
Изменение и событие сохраняются в одной транзакции. При доставке повторно
отправляется тот же JSON с прежним `event_id`. Порядок доставки не считается
порядком изменений.

- Каталог: применяй только версию новее сохраненной для этого материала.
  Публикация несет тип, формат, заголовок (до 256 символов), темы и оценку
  времени. Архивация, удаление и скрытие отправляют `tombstone: true` без
  метаданных. Восстановление возвращает ту же ревизию с более новой версией
  события. Откат публикует новую ревизию с восстановленным текстом.
  Частные черновики в поток не попадают.
- Рейтинг: `material.corrected` и `material.withdrawn` содержат
  `payload.invalidated_revision_id` замененной или скрытой публикации.
  Связывай компенсации с материалом и этой ревизией; дедуплицируй по
  `event_id`. Для пары скрытие/восстановление применяй последнюю версию
  события для данной ревизии. `material.restored` снимает ограничение
  по `revision_id`, но не создает новое начисление. Не пропускай
  исправление другой ревизии из-за более нового события каталога.
  Причина и ID модератора не передаются.
- Вклад: дедуплицируй по `event_id`. После merge есть одно событие автора и
  отдельное событие каждого действующего рецензента, чей голос учтен в ревью.
  `decision` передается отдельно, в том числе `request_changes`. Событие не
  начисляет баллы; правила принадлежат сервису рейтинга.
- Чтение: `ConfirmMaterialRead` принимает `material_id` и текущий
  опубликованный `revision_id`. Нужен подтвержденный пользователь. Один
  пользователь может подтвердить версию один раз. Результат содержит
  `evidence: self_reported`. Обычный просмотр не отправляет событие.

В этих топиках нет исходников, вложений и текста обсуждений. Старый
`content.content-item-events` сохраняет формат для внутренних потребителей;
не используй его как открытый каталог или источник рейтинга.

## Снимок каталога

Для `SnapshotMaterials` нужен сервисный токен, пользователь не нужен.
На первом запросе опусти `watermark` и `after_id`. Повторяй запрос с тем же
`watermark` и последним `next_after_id`, пока он не станет пустым. Размер
страницы по умолчанию 50, максимум 100. Старые опубликованные записи после
миграции имеют версию 0.

Для загрузки новой проекции сначала запомни конечные offsets всех partitions
`content.material.v1`, затем выгрузи снимок. После выгрузки читай Kafka с
сохраненных offsets, применяя версии выше `watermark` и игнорируя дубли и
устаревшие версии отдельных материалов. Удаления хранятся в снимке как
tombstones. При смене числа partitions или потере сохраненных offsets загрузи
снимок заново. При выключенных событиях снимок работает, но онлайн-обновления
не доставляются; после включения начни с нового снимка.

Подтверждения чтения и события вклада не входят в каталог. Для них используй
отдельные consumer groups и ключ `event_id` для повторной доставки.

## Проверка доступности перед показом

`CONTENT_GRPC_CATALOG_TOKEN` дает доступ к `ContentService.SnapshotMaterials`
и `MaterialCatalogService.CheckMaterialAvailability` без actor. Это отдельный токен: токен Gateway,
Media или модерации использовать нельзя. Старый сервисный токен по-прежнему
работает для снимка. С каталожным токеном нельзя читать текст материалов,
черновики, менять публикации или подтверждать чтение.

`CheckMaterialAvailability` принимает 1-100 уникальных пар `material_id` и
`revision_id`. Возвращает только пары из запроса, у которых редакция до сих пор
опубликована и не скрыта модерацией. В ответе нет заголовков, текста и файлов.
Пустой результат означает, что ни одна запрошенная редакция не доступна.
При ошибке проверки не показывай ресурс из отставшей проекции или старого плана.

## Проверка доставки

Для `TestModerationKafkaDelivery` нужны пустая тестовая БД с миграциями
и отдельный пустой топик Kafka. Задай `COMPONENT_TEST_DSN`,
`COMPONENT_TEST_KAFKA_BROKER` и `COMPONENT_TEST_MATERIAL_TOPIC`, затем запусти:

```bash
go test -tags=component ./tests/component -run '^TestModerationKafkaDelivery$' -count=1
```
