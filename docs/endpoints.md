# Endpoints

## HTTP

- `GET /` возвращает базовую информацию о сервисе.
- `GET /healthz` liveness probe.
- `GET /readyz` readiness probe с проверкой PostgreSQL.
- `GET /metrics` Prometheus metrics.

Пример:

```bash
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
curl http://localhost:8080/metrics
```

## gRPC

Сервис: `overmindv.content.ContentService`

Для всех операций нужны метаданные `authorization: Bearer <token>` и
`x-user-id: <uuid>`. Используй случайный `CONTENT_GRPC_SERVICE_TOKEN` длиной от 32
байт. Без него операции отклоняются, HTTP-пробы не меняются. Gateway должен брать UUID из
проверенной сессии, а не пересылать заголовок браузера. Поля `created_by` и
`updated_by` в запросах сохранены для совместимости, но игнорируются.

Это внутренний API. Не открывай gRPC в публичную сеть; передавай токен за
пределами локальной среды только по защищенному каналу.

- Автор видит свой материал и его историю, может изменить или удалить их.
- Остальные пользователи видят только опубликованные материалы. `GetContentItem`
  и `ListContentItems` возвращают им опубликованную ревизию и ее вложения, даже
  если автор уже сохранил новую правку.
- Недоступный по ID материал возвращает `NotFound`, как и отсутствующий.
  Назначение на ревью предложения не дает доступа к черновику материала.

- `CreateContentItem`
- `GetContentItem`
- `ListContentItems`
- `ListContentCatalog`
- `UpdateContentItem`
- `DeleteContentItem`
- `CreateContentRevision`
- `SaveContentDraft`: сохраняет текст, заголовок, темы и вложения
  одной транзакцией. Передай `revision.expected_revision_id` и
  `draft_metadata`. Для устаревшей версии вернется `ABORTED`;
  метаданные уже опубликованного материала этим методом не меняются.
- `ListContentRevisions`
- `PublishContentItem`
- `ArchiveContentItem`

Новый материал создается как черновик. `UpdateContentItem` меняет только
метаданные черновика; после публикации эти поля заблокированы, пока для них
нет версионирования. Для правки текста используй `CreateContentRevision`: она
сдвигает `current_revision_id`, не меняя `published_revision_id`.

### Каталог и учебные поля

`learning` при создании или обновлении черновика задает до 8 UUID тем,
до 8 результатов обучения по 256 байт и оценку времени до 480 минут.
Ноль минут означает, что оценка не задана. Отсутствующее поле при обновлении
оставляет старые значения; `{}` очищает все учебные поля. Настрой
`CONTENT_ENTITIES_URL`: темы проверяются через `GET /v1/topics/{id}` перед записью.
Неактивная или отсутствующая тема дает `InvalidArgument`, сбой `entities` дает
`Unavailable`. Архивирование темы после привязки обрабатывается отдельно в OVM-134.

`ListContentCatalog` возвращает поля карточки без исходников, с фильтрами
`topic_id`, `author_id`, `status`. Все фильтры применяются вместе. По умолчанию
20 записей, максимум 50. Для следующей страницы передай `next_cursor` как
`cursor` с теми же фильтрами. Для опубликованного материала `revision_id` всегда
указывает на опубликованную ревизию, даже в ответе автору. Чужие черновики и архив
не видны. Для нового каталога используй этот RPC; старый `ListContentItems`
сохраняет прежний формат. Go-клиент: `github.com/overmindv/content/pkg/api/content`.

`GetPublishedContentItem` возвращает только опубликованную ревизию, даже если
запрос делает автор. Токен сервиса и ID пользователя обязательны.

Для сохранения ревизии, публикации и архивации передай в `expected_revision_id`
текущий ID ревизии из ответа автора. Если за это время появилась другая правка,
сервис вернет `Aborted`. Отсутствующий или неверный UUID дает `InvalidArgument`.

Публикация делает текущую ревизию доступной читателям. Архивация выводит материал
из чтения и запрещает новые правки и повторную публикацию (`FailedPrecondition`).
Повтор публикации той же версии или архивации с тем же ID не создает еще одно
событие. Все три операции доступны только автору.

Для пилота публикуется только Markdown. Typst можно сохранить как исходник
черновика, но сервис его не запускает. Markdown проверяется при сохранении и
перед публикацией: raw HTML и встроенные изображения запрещены. В ссылках
разрешены HTTPS без логина и пароля и якоря внутри документа. HTML снаружи
блока кода отклоняется; примеры HTML в блоке кода остаются текстом.

Лимиты: 128 КиБ на исходник, 128 ссылок по 2048 байт, 32 вложения и 512 КиБ на
gRPC-запрос. Ошибки проверки возвращаются как `InvalidArgument` без фрагментов
исходника. Запросы больше транспортного лимита отклоняются до обработчика.

Перед подключением рендера проверь старые публикации: эта проверка действует
на сохранение и публикацию, а не исправляет ранее сохраненный текст. В клиенте
нельзя включать raw HTML или запускать Typst; проверяй URL и при выводе ссылок.

### Предложения правок

- `OpenChangeProposal`: передай ID материала, ID его опубликованной ревизии и
  новый текст в Markdown. Автор берется из gRPC-метаданных. На один материал у
  автора может быть одно открытое предложение; повтор дает `AlreadyExists`.
- `GetChangeProposal`: автор предложения и автор материала видят текущее
  состояние и последнюю правку. Другие пользователи получают `NotFound`.
- `AppendChangeProposalRevision`: автор открытого предложения передает текущий
  `expected_head_id`. При совпадении создается новая ревизия с указателем на
  предыдущую; при конфликте сервис возвращает `Aborted`.
- `RebaseChangeProposal`: автор передает текущий `expected_head_id`,
  ID новой опубликованной версии в `base_revision_id` и исправленный текст.
  Если опубликованная версия уже сменилась, ответ содержит `Aborted` с
  кодом `MERGE_CONFLICT` в сообщении. У новой ревизии нет прежних одобрений.
  Без `attachments` сохраняются вложения последней правки, если она уже
  хранит их снимок. Иначе берутся вложения новой основы.
- `CloseChangeProposal`: автор закрывает предложение без удаления истории.
  Повтор закрытия возвращает то же состояние. Закрытое предложение нельзя
  редактировать; можно открыть новое.
- `MergeChangeProposal`: владелец материала передает ID предложения и
  `expected_head_id`. Нужен кворум действующих назначений на эту ревизию;
  обсуждения по ней должны быть закрыты. Если основа устарела, сервис отвечает
  `Aborted` с `MERGE_CONFLICT`. Перенос на новую основу требует нового ревью.
- Если правка содержит вложения, первый запрос ставит привязку в очередь
  и отвечает `FailedPrecondition` с `ATTACHMENTS_PENDING`, пока Media не подтвердит ее. Клиент
  повторяет тот же запрос; опубликованная версия до подтверждения не меняется.
  Неиспользованная привязка освобождается через 15 минут. Повтор успешного
  слияния возвращает прежний ID ревизии без нового события.

До слияния правка хранится отдельно и не меняет публикацию или черновик.
При слиянии публикация, статус предложения и запись outbox меняются вместе.
Если владелец уже открыл отдельный черновик, он сохраняется. Комментарий к
ревизии ограничен 1024 байтами.

- `ListChangeProposalHistory` возвращает ID, родителя, основу ревизии, порядковый номер, автора,
  время и комментарий. Тела ревизий в ответ не входят. Порядок от новых к старым,
  размер страницы 20 по умолчанию и не более 50. Передай `next_before_ordinal`
  как `before_ordinal` следующего запроса; ноль означает, что страниц больше нет.
- `GetChangeProposalDiff` сравнивает версию основания с текущей правкой или с
  ревизией, переданной в `revision_id`. Ревизия из другого предложения дает
  `NotFound`. Ответ в формате unified diff, для вывода как обычный текст.
- Сравнение ограничено 128 КиБ на исходник, 8192 строками суммарно и бюджетом
  вычисления 50 мс. При превышении лимита входа, времени или размера ответа
  (32 КиБ) приходит `truncated: true`, возможно без текста. Частичный ответ
  содержит только целые блоки и не предназначен для применения как патч.
  Одновременно выполняется до четырех сравнений; остальные получают `ResourceExhausted`.
  Чтение исходников из БД прерывается через 1 секунду.

История и сравнение доступны автору предложения, автору материала и
рецензентам, назначенным на текущую ревизию открытого предложения.

### Рецензирование правки

- `CreateReviewThread` закрепляет обсуждение за ревизией предложения. Номер
  строки отсчитывается с единицы; ноль относится ко всей ревизии.
- `ReplyToReviewThread` добавляет ответ, `SetReviewThreadResolved` закрывает или
  снова открывает обсуждение. Текст хранится как обычный текст, не HTML, до 4096 байт.
- `ListReviewThreads` и `ListReviewReplies` возвращают записи по возрастанию ID.
  Передай `next_after_id` как `after_id` следующей страницы. По умолчанию 20 записей,
  максимум 50. Треды и ответы остаются доступными после закрытия предложения.
- `SubmitReviewDecision` принимает `approve` или `request_changes` только для
  текущей ревизии открытого предложения. Для `request_changes` нужна причина.
  Повтор того же решения возвращает исходную запись. Старый ID ревизии дает `Aborted`.
- `GetReviewRevisionStatus` возвращает назначения, решения и итог по ревизии.
  `pending` означает, что назначенные участники еще не проголосовали.
  `waiting_candidates` возвращается с причиной `initial_reviewers` или
  `tiebreak_reviewer`. Совпадение двух голосов или большинство из трех
  дает `approved` либо `changes_requested`. Используй итог только при
  `current: true`. Решения с `legacy: true` не входят в кворум.

Решение могут принять только назначенные рецензенты. Автор предложения не
может голосовать. При новой правке назначения и решения не переносятся.
Отзыв назначения исключает голос из подсчета; запись остается в БД.
Автор материала получает приоритет, если он входит в список кандидатов.
Когда он недоступен, оба места заполняются по рейтингу.

Назначения и отзыв выполняются на уровне хранилища. В gRPC нет метода для
передачи списка кандидатов. Пока источник прав рецензирования и тематического
рейтинга не подключен, ревью остается в ожидании назначения.

### История ревизий материала

`ListContentRevisionHistory` доступен только владельцу. Метод возвращает
краткие сведения без текста ревизий, до 50 записей за вызов. Для следующей
страницы передайте `next_before_revision` как `before_revision`. Ноль означает
конец списка. Ссылка на исходную ревизию для отката пока не заполняется.

Примеры:

```bash
grpcurl -plaintext -H "authorization: Bearer ${CONTENT_GRPC_SERVICE_TOKEN}" \
  -H 'x-user-id: 11111111-1111-4111-8111-111111111111' \
  -d '{"type":"article","status":"draft","title":"Starter article","slug":"starter-article","format":"markdown","source":"# Starter article","tags":["go","content"]}' \
  localhost:9090 overmindv.content.ContentService/CreateContentItem

grpcurl -plaintext localhost:9090 list
```
### Вложения

Content хранит снимок файлов для каждой ревизии. При сохранении ревизии
или предложения отсутствие поля `attachments` сохраняет предыдущий набор,
а `attachments: {}` оставляет новую ревизию без файлов. У первого предложения
исходный набор берется из опубликованной ревизии.

Явно добавленные файлы проверяются в Media от имени автора. Привязка
доставляется из Postgres после коммита; публикация с неподтвержденными
привязками возвращает `FAILED_PRECONDITION`. Повторная доставка
использует тот же номер версии. При закрытии предложения освобождаются
только его привязки. Старые редакции опубликованного материала сохраняются.

Для доставки задай `CONTENT_MEDIA_URL` и отдельный `CONTENT_MEDIA_TOKEN`,
совпадающий с `MEDIA_CONTENT_TOKEN` в Media. Без этой пары добавление
файлов недоступно.
