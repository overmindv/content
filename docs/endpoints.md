# Endpoints

## HTTP

- `GET /` возвращает базовую информацию о сервисе.
- `GET /healthz` liveness probe.
- `GET /readyz` readiness probe с проверкой PostgreSQL.
- `GET /metrics` Prometheus metrics.

Пример:

```bash
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
curl http://localhost:8080/metrics
```

## gRPC

Сервис: `overmindv.content.ContentService`

Для всех операций нужны метаданные `authorization: Bearer <token>` и
`x-user-id: <uuid>`. Используй случайный `CONTENT_GRPC_SERVICE_TOKEN` длиной от 32
байт. Без него операции отклоняются, HTTP-пробы не меняются. Gateway должен брать UUID из
проверенной сессии, а не пересылать заголовок браузера. Поля `created_by` и
`updated_by` в запросах сохранены для совместимости, но игнорируются.

Это внутренний API. Не открывай gRPC в публичную сеть; передавай токен за
пределами локальной среды только по защищенному каналу.

- Автор видит свой материал и его историю, может изменить или удалить их.
- Остальные пользователи видят только опубликованные материалы. `GetContentItem`
  и `ListContentItems` возвращают им опубликованную ревизию и ее вложения, даже
  если автор уже сохранил новую правку.
- Недоступный по ID материал возвращает `NotFound`, как и отсутствующий.
  Отдельных прав для администратора и назначенного рецензента пока нет.

- `CreateContentItem`
- `GetContentItem`
- `ListContentItems`
- `UpdateContentItem`
- `DeleteContentItem`
- `CreateContentRevision`
- `ListContentRevisions`
- `PublishContentItem`
- `ArchiveContentItem`

Новый материал создается как черновик. `UpdateContentItem` меняет только
метаданные черновика; после публикации эти поля заблокированы, пока для них
нет версионирования. Для правки текста используй `CreateContentRevision`: она
сдвигает `current_revision_id`, не меняя `published_revision_id`.

Для сохранения ревизии, публикации и архивации передай в `expected_revision_id`
текущий ID ревизии из ответа автора. Если за это время появилась другая правка,
сервис вернет `Aborted`. Отсутствующий или неверный UUID дает `InvalidArgument`.

Публикация делает текущую ревизию доступной читателям. Архивация выводит материал
из чтения и запрещает новые правки и повторную публикацию (`FailedPrecondition`).
Повтор публикации той же версии или архивации с тем же ID не создает еще одно
событие. Все три операции доступны только автору.

Для пилота публикуется только Markdown. Typst можно сохранить как исходник
черновика, но сервис его не запускает. Markdown проверяется при сохранении и
перед публикацией: raw HTML и встроенные изображения запрещены. В ссылках
разрешены HTTPS без логина и пароля и якоря внутри документа. HTML снаружи
блока кода отклоняется; примеры HTML в блоке кода остаются текстом.

Лимиты: 128 КиБ на исходник, 128 ссылок по 2048 байт, 32 вложения и 512 КиБ на
gRPC-запрос. Ошибки проверки возвращаются как `InvalidArgument` без фрагментов
исходника. Запросы больше транспортного лимита отклоняются до обработчика.

Перед подключением рендера проверь старые публикации: эта проверка действует
на сохранение и публикацию, а не исправляет ранее сохраненный текст. В клиенте
нельзя включать raw HTML или запускать Typst; проверяй URL и при выводе ссылок.

### Предложения правок

- `OpenChangeProposal`: передай ID материала, ID его опубликованной ревизии и
  новый текст в Markdown. Автор берется из gRPC-метаданных. На один материал у
  автора может быть одно открытое предложение; повтор дает `AlreadyExists`.
- `GetChangeProposal`: автор предложения и автор материала видят текущее
  состояние и последнюю правку. Другие пользователи получают `NotFound`.
- `AppendChangeProposalRevision`: автор открытого предложения передает текущий
  `expected_head_id`. При совпадении создается новая ревизия с указателем на
  предыдущую; при конфликте сервис возвращает `Aborted`.
- `CloseChangeProposal`: автор закрывает предложение без удаления истории.
  Повтор закрытия возвращает то же состояние. Закрытое предложение нельзя
  редактировать; можно открыть новое.

Правки предложения хранятся отдельно и не меняют ни опубликованную версию, ни
черновик материала. Комментарий к ревизии ограничен 1024 байтами. Список истории,
назначение рецензентов, проверка конфликта при принятии и публикация правки
появятся в следующих задачах. Текст предложения не отправляется в Kafka.

Примеры:

```bash
grpcurl -plaintext -H "authorization: Bearer ${CONTENT_GRPC_SERVICE_TOKEN}" \
  -H 'x-user-id: 11111111-1111-4111-8111-111111111111' \
  -d '{"type":"article","status":"draft","title":"Starter article","slug":"starter-article","format":"markdown","source":"# Starter article","tags":["go","content"]}' \
  localhost:9090 overmindv.content.ContentService/CreateContentItem

grpcurl -plaintext localhost:9090 list
```
